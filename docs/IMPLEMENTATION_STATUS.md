# DAYFLOW implementation status

Этот документ различает реализованный код, проверенное состояние облака и незавершённые возможности. Наличие экрана само по себе не означает, что весь сценарий готов к Production.

## Реализовано в исходном коде
- Основа авторизации, профиль пользователя, настройки и три палитры.
- Календарь, задачи, события, категории и подзадачи.
- Focus-сессии, XP, достижения и стадии виртуального компаньона.
- Inbox: создание, статусы, архивирование и удаление.
- Цели: дата, прогресс и жизненный цикл.
- Записи расписания напоминаний и отмена; фактической доставки push/email пока нет.
- Базовая фактическая аналитика по сохранённым задачам, Focus, целям и напоминаниям.
- Assistant capture сохраняет запрос в Inbox; вызова AI-модели пока нет.
- Финансы: доходы/расходы с привязкой категорий, бюджеты на неделю/месяц/год и расчёт исполнения по периоду, валюте и категории. Прогресс рассчитывается по загруженным последним 250 операциям; конвертации валют и полной исторической агрегации пока нет.
- Основа CRM: контакты и журнал взаимодействий. Follow-up, напоминания и связь контактов с задачами ещё не завершены.
- Личный дневник самочувствия: добровольные пользовательские записи сна, настроения, энергии и заметок; сводка средних показателей и визуализация сна по последним семи записям. Это описательная статистика, не медицинская оценка. Внешние HealthKit/Health Connect интеграции не реализованы.

## Проверенные факты по облаку и CI
- История Supabase проверена: все шесть миграций с версиями 202611180001–202611190005 присутствуют на удалённом проекте и совпадают с локальной историей.
- CI выполняет ESLint, TypeScript typecheck, unit tests и production build.
- SQL job CI поднимает временный локальный Supabase и применяет все миграции с нуля.
- SQL-регрессии CI: Phase 2 identity/preferences RLS, Phase 3 calendar/schema RLS, Phase 4A database foundation/isolation, Phase 4B Inbox/Goals RLS, Phase 5 personal modules RLS и timezone validation.
- Phase 5 проверяет изоляцию двух пользователей для шести таблиц финансов, контактов и дневника здоровья, включая SELECT/INSERT/UPDATE/DELETE и защиту связей между владельцами.
- Полноценного браузерного E2E-покрытия пока нет; успешный CI не заменяет ручную проверку реальных пользовательских сценариев в браузере.

## Не завершено / запланировано
- Финансы: пагинация/полная агрегация истории, отчёты по периодам, редактирование/удаление категорий и бюджетов, интерфейс регулярных операций и конвертация валют.
- CRM: поиск/сегментация, follow-up, напоминания и связь контактов с задачами.
- Здоровье: расширенные недельные/месячные сравнения и подключение внешних источников только по явному согласию пользователя.
- Push/email требуют доверенного фонового worker и настройки провайдера.
- Голосовое/визуальное извлечение задач, OpenAI assistant, календарная синхронизация и нативные iOS/Android-приложения не реализованы.
- Для совместной работы есть база данных, но приглашения, membership, авторизация и UI сценарии нельзя считать готовыми.
- Полная проверка двух пользователей для всех таблиц и Storage, доступности и production security review ещё требуются.

## Локальная проверка
Из корня репозитория:

```powershell
npm.cmd ci
npm.cmd run lint
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
```

Успешная сборка не заменяет изолированные Supabase RLS-тесты и браузерные E2E. Не включать .env.local, .git, node_modules и .next в архивы исходников.

## Безопасность базы данных
Каждую миграцию проверять как часть упорядоченного набора. Перед production-изменениями делать резервную копию и применять изменения только после явного согласования. Никогда не использовать supabase db reset против существующего проекта.
